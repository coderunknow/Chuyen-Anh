### #26 — 2026-10-13 — DONE
Implemented the distractor-quality improvement selected in entry #25. One hypothesis was tested and **rejected before any code was written**: a suspected systematic bias that placed the correct answer away from option 1 did not exist — over 48 real questions in the unmodified app the answer landed in each slot `[9, 12, 11, 16]`, i.e. `shuffle` is a uniform Fisher–Yates shuffle. Nothing was changed on the basis of that guess, and this entry records the refutation rather than a “fix”.

The real defect was measured instead: in the real application only **38.2%** of the three distractors shared a part of speech with the headword (55/144; exact-string comparison 25.7%), so most options were eliminable at a glance and a word → Vietnamese-gloss question was close to a free pick. Data measurements that shaped the fix: 910 of 913 records have at least three same-part-of-speech peers, only `grammar` (2 records) and `conj` (1 record) do not; 5 glosses are shared by exactly 2 entries each, which the previous filter could surface as two identical options; and the cloze builder never checked its options against the sentence it displayed.

Implementation (`index.html`, question composition only): `posTokens()`/`sharesPos()` match free-text `pos` values by token overlap so `v/n` shares a class with both `v` and `n`; `distractors(vocabulary, current, field, { usable })` builds a same-part-of-speech pool and an other-part-of-speech pool, shuffles each, and takes same-POS first so the fallback only applies where the dataset is too small; candidates whose normalized text repeats the answer or another option are skipped, which removes the duplicate-gloss problem; `wordsIn()` plus the cloze `usable` filter keeps words already printed in the displayed sentence out of the options. No vocabulary record, scheduler rule, storage key, persisted field, import/export field, dependency or workflow changed.

Measured effect with the same probe on the real app, before and after: same-POS distractors 38.2% → **100%** (144/144), with the correct-answer slot distribution staying effectively uniform (`[15, 14, 9, 10]` → `[10, 10, 14, 14]`), and no duplicate option text in either run.
